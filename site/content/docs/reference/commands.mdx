## Setting up

Getting the proxy in front of your tools, and taking it back out.

### `tokunseba init`

Point every supported tool at the proxy and start it in the background.

```bash
tokunseba init [OPTIONS]
```

| Option | Default | What it does |
|---|---|---|
| `--no-service` | — | Do not install the background service. |
| `--no-hooks` | — | Do not register Claude Code hooks. |
| `--with-mcp` | — | Register the MCP expand tool. Only needed for agents with no shell; it costs one background process per session. |
| `-y`, `--yes` | — | Do not ask. For scripts and images. |
| `--dry-run` | — | Print what it would change and stop. |

### `tokunseba on`

Re-apply the proxy configuration to every tool.

```bash
tokunseba on
```

### `tokunseba off`

Restore every tool's original configuration. The proxy stops being used immediately.

```bash
tokunseba off
```

### `tokunseba uninstall`

Remove the background service and restore every tool.

```bash
tokunseba uninstall
```

### `tokunseba apps status`

Show what an application launched from the Dock would actually connect to.

```bash
tokunseba apps status
```

### `tokunseba apps on`

Make Dock-launched applications route through the proxy, after saying how.

```bash
tokunseba apps on [OPTIONS]
```

| Option | Default | What it does |
|---|---|---|
| `-y`, `--yes` | — | Do not ask for confirmation. |

### `tokunseba apps off`

Stop routing Dock-launched applications. Terminals are not affected.

```bash
tokunseba apps off
```


| Option | Default | What it does |

### `tokunseba advise`

Ask the local judge what your prompts looked like, and what routing them would save.

```bash
tokunseba advise [OPTIONS]
```

This runs offline over conversations that already happened, so it costs nothing, adds no latency, and cannot change an answer. It is the honest way to find out whether routing by prompt is worth switching on before you switch it on.

| Option | Default | What it does |
|---|---|---|
| `--since` | `30d` | — |
| `--limit` | `100` | Conversations to judge. |
| `--to` | `claude-sonnet-5` | The smaller model to name as the destination. |

### `tokunseba replay`

Re-run recorded traffic under a different configuration, and report the difference.

```bash
tokunseba replay [OPTIONS]
```

Nothing is sent anywhere and nothing of yours is written: the replay works from the request bodies already on disk, and its ledger and blob store live in a temporary directory that is deleted when it finishes. It is the way to find out what a setting would do to your own work before committing to it.

Tier 3 is not replayed. It decides which model answers, and no offline pass can know what a different model would have said. Use `tokunseba advise` for that question.

| Option | Default | What it does |
|---|---|---|
| `--since` | `7d` | — |
| `--limit` | `500` | Most recent requests to replay. |
| `--tier` | — | Replay as though only these tiers were on. Repeatable. |
| `--set` | — | Override one setting for the replay only, e.g. thresholds.truncate_tokens=3000. Repeatable. |
| `--verbose` | — | List the requests that would change. |

## Choosing the model

Endpoints, routing rules, and the judge.

### `tokunseba models list`

Show every configured upstream and every model seen going through them.

```bash

```

| Option | Default | What it does |
|---|---|---|
| `--check` | — | Also ask each endpoint whether it answers. Sends no key and no prompt. |
| `--since` | `7d` | How far back to look for models you actually used. |

### `tokunseba models add`

Add a model endpoint, such as a DeepSeek key or a second ollama host.

```bash
tokunseba models add NAME BASE-URL [OPTIONS]
```

Only the address is stored. Keys stay wherever your client already keeps them and are forwarded from the request, so nothing secret is written to disk here.

| Option | Default | What it does |
|---|---|---|
| `--kind` | — | Which protocol it speaks. Guessed from the URL when omitted. |
| `--check`, `--no-check` | `True` | Probe the endpoint before saving it. |

### `tokunseba models rm`

Remove a model endpoint.

```bash
tokunseba models rm NAME
```

### `tokunseba models check`

Ask every configured endpoint whether it answers. No key, no prompt, no cost.

```bash
tokunseba models check
```

## Using it without the proxy

One command, one tool, or from Python.

### `tokunseba run`

Run a shell command and print its output already compressed.

```bash
tokunseba run CMD...
```

Use it as: tokunseba run -- pytest -q

### `tokunseba wrap`

Run a tool with tokunseba in its environment.

```bash
tokunseba wrap TOOL ARGS...
```

This is the reliable way in. Writing a tool's settings file can be overridden by an exported base URL, and several launchers export one. Wrapping sets the variables on the tool's own process, so nothing inherited can win, and it changes nothing on disk.

Examples: tokunseba wrap claude · tokunseba wrap codex -- --model gpt-5

### `tokunseba wrap-any`

Run any command with every tokunseba base URL exported.

```bash
tokunseba wrap-any COMMAND...
```

Use it for a tool that is not in the known list, or for a whole shell: tokunseba wrap-any -- zsh

### `tokunseba wrappable`

List the tools tokunseba can run, and which are installed here.

```bash
tokunseba wrappable
```

### `tokunseba mcp`

Run the MCP server exposing the expand tool, for agents without a shell.

```bash
tokunseba mcp
```

### `tokunseba hook`

Hook entry point. Reads the host tool's JSON event on stdin.

```bash
tokunseba hook [WHICH]
```

## History

How long it keeps things, and deleting what is past that.

### `tokunseba retention show`

Show the current window, and how much is actually stored.

```bash
tokunseba retention show
```

### `tokunseba retention keep`

Keep history for WINDOW: 24h, 30d, 6w, 6m, 1y, or forever.

```bash
tokunseba retention keep WINDOW [OPTIONS]
```

Examples: tokunseba retention keep 1y · tokunseba retention keep forever

| Option | Default | What it does |
|---|---|---|
| `--bodies` | — | A shorter window for stored request bodies, which are the bulkiest part. Defaults to 14d. |

### `tokunseba retention auto`

Turn the once-a-day automatic prune on or off.

```bash
tokunseba retention auto STATE
```

### `tokunseba retention prune`

Delete everything older than the window, now.

```bash
tokunseba retention prune [OPTIONS]
```

| Option | Default | What it does |
|---|---|---|
| `--keep` | — | Prune to this window just this once, without changing the setting. |

### `tokunseba prune`

Delete history older than the retention window.

```bash
tokunseba prune [OPTIONS]
```

The window itself lives in the config; see and change it with `tokunseba retention`.

| Option | Default | What it does |
|---|---|---|
| `--days` | — | Override the configured retention window for this run. |

## Exit codes

| Code | Meaning |
|---|---|
| 0 | It worked, or there was nothing to do |
| 1 | It refused, and said why. A missing handle, an unknown key, a declined confirmation |
| 2 | The command line itself was wrong. Click's own error |

## Environment variables

| Variable | What it does |
|---|---|
| `TOKUNSEBA_HOME` | Where the config, ledger, blobs and backups live. Default `~/.tokunseba` |
| `TOKUNSEBA_NO_SESSION_ENV` | Do not read or write login-session variables. Used by tests and containers |
| `TOKUNSEBA_NO_WARM` | Never load the local judge at startup, whatever the config says |
| `TOKUNSEBA_LAYA_SMOKE` | Opt in to the test that downloads and runs the real judge model |
